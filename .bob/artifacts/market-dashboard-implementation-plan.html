Gaps to fix before or during scaffolding

  1. CI points at the wrong directory. The workflow runs npm at the repository root, but the app will live in finance-app/. Add defaults.run.working-directory: finance-app and set cache-dependency-path: finance-app/package-lock.json.
  2. The CI install step needs a lockfile. setup-node with cache: npm fails without one. Commit package-lock.json and switch npm install to npm ci.
  3. CI silently passes with no scripts. --if-present makes lint, test and build succeed when a script is missing. Remove it once the scripts exist, so CI cannot go green on an empty app.
  4. Workshop Part 2 says to push from finance-app as its own repo, while the CI and templates sit at this repo's root. Pick one layout. This plan assumes one repo, app in finance-app/.
  5. Node version drift. Add an engines field and a .nvmrc set to 20. Local v24 should still work, but document it.
  6. The README refers to a “reference folder” that is not present. Treat it as stale and remove or fix the reference.

3. Architecture

Four layers with one-way dependencies. The UI never knows about Yahoo; the proxy never knows about React.

Browser (Vite + React)
 ├─ UI layer         components/ pages/         render only, no fetching
 ├─ State layer      hooks/ (TanStack Query)    cache, loading, errors, URL state
 ├─ Domain layer     domain/                    types, window config, metrics (pure)
 └─ Data layer       services/                  MarketDataService interface
        ├─ HttpMarketDataService   ──►  /api/*  (Vite dev proxy / same-origin in prod)
        └─ MockMarketDataService   ──►  fixtures (tests, offline workshop)

Node proxy (finance-app/server)
 ├─ routes/          validate input (zod), map errors to HTTP codes
 ├─ yahooClient      the only file that imports yahoo-finance2
 └─ cache            in-memory TTL cache per (symbol, window)

Key design rule. Everything after yahooClient is provider-neutral. If Yahoo access breaks, you replace one file, or flip VITE_DATA_SOURCE=mock, and the rest of the app is unaffected. The workshop notes ask for exactly this resilience.

6. Data service abstractions

Domain contract

type WindowId = 'day' | 'week' | 'quarter';

interface Quote {
  symbol: string; name: string; currency: string;
  price: number; change: number; changePct: number;
  marketState: 'PRE' | 'REGULAR' | 'POST' | 'CLOSED';
  asOf: number;               // epoch ms
}
interface PricePoint { t: number; close: number }
interface Series {
  symbol: string; window: WindowId;
  points: PricePoint[];       // ascending by t, nulls removed
  previousClose?: number;
}

interface MarketDataService {
  getQuotes(symbols: string[]): Promise<Result<Quote>[]>;
  getSeries(symbol: string, window: WindowId): Promise<Series>;
}

Time-window configuration

Define once in domain/windows.ts. UI, proxy and tests all read from it.

WindowRangeIntervalProxy cache TTLNotes
dayCurrent trading session5 min~60 sIf the market is closed, show the last completed session and label it.
weekLast 7 calendar days (about 5 trading days)30 min to 1 h~5 minGaps over weekends are expected. Do not interpolate.
quarterTrailing ~90 days1 day~1 h“Last quarter” is ambiguous. This plan uses trailing 3 months, not the previous calendar quarter. Record the decision in the README.

Exact intervals should be confirmed against what Yahoo returns for each range during Phase 2.

Proxy endpoints

EndpointBehavior
GET /api/quotes?symbols=IBM,MSFTValidates symbols (pattern and max count), returns per-symbol results so one bad ticker does not fail the batch.
GET /api/history?symbol=IBM&window=weekValidates both params, calls the chart endpoint of yahoo-finance2, returns normalized points.
GET /api/healthUsed by local validation and smoke checks.

Use the library's chart call for history rather than the legacy historical call, which Yahoo has been deprecating. Confirm the exact method against the installed version.

Normalization and resilience rules

  • Drop points where close is null or non-finite (common on holidays and thin trading).
  • Sort ascending and de-duplicate by timestamp.
  • Fetch per symbol with Promise.allSettled. A failed peer shows an error card, and the other four stay usable.
  • Keep proxy cache keys as symbol:window and serve stale data on upstream failure, marked stale: true.
  • Allow-list tickers on the server when in default mode, which keeps the proxy from becoming an open Yahoo relay. Loosen this in the later user-selected-company feature (section 12).

Implementation selection

services/index.ts returns MockMarketDataService when VITE_DATA_SOURCE=mock and HttpMarketDataService otherwise. Mock mode makes demos, CI and component tests independent of Yahoo's availability.

7. Charting approach

  • One comparison chart, normalized. Different share prices (IBM vs. Salesforce) cannot share a raw-price axis. Rebase each series to (close / firstClose − 1) × 100, so all lines start at 0% and show relative performance. Implement this in domain/metrics.ts as a pure, unit-tested function.
  • Per-window formatting. Day shows time-of-day ticks; week shows weekday plus time; quarter shows dates. Tooltip shows raw price and % change.
  • IBM emphasis. IBM gets a heavier stroke, and peers use a fixed accessible palette in chartTheme.ts. Direct labels or a legend must not rely on color alone.
  • Adapter boundary. PriceChart is the only file importing Recharts. Its props are domain types, so swapping to another chart library touches one component.
  • Summary cards for “current day”. Quote cards carry price and daily change. The day chart supplements them with the intraday shape.
  • Accessibility. Provide a text summary (aria-label or visually hidden) and the ranking table as a non-visual equivalent.

8. State management strategy

StateKindWhere it lives
Quotes, series (loading / error / data)Server stateTanStack Query. Keys: ['quotes', symbols], ['series', symbol, window].
Active window, selected tickersShareable UI stateURL search params through useDashboardParams (?w=week&t=IBM,MSFT). Back and forward navigation and link sharing work with no extra code.
Derived metrics (rebased series, ranking)DerivedComputed with useMemo from query data. Not stored.
Ephemeral UI (hover, popovers)LocalComponent useState.

No Redux or Zustand at this stage. Query defaults: staleTime aligned to the proxy TTL, retry: 2 with backoff, and refetchInterval only for the day window while the market is open.

9. Error handling

FailureWhere caughtUser-visible result
Yahoo unreachable or rate-limitedProxy returns 502 or 429; serves stale cache when availableData with a “Stale as of …” badge, or an ErrorPanel with Retry
Invalid or unknown symbolProxy returns 400 / 404 with a typed error codeCard-level message (“Symbol not found”). Other cards unaffected.
Partial or empty seriesnormalize.ts and ChartCardEmptyState (“No data for this window”). Market-closed notice for day.
Network failureHttpMarketDataService throws a typed DataErrorQuery retries, then ErrorPanel
Render exceptionErrorBoundary per panelOne panel shows a fallback. The page keeps working.
Bad query-string valuesuseDashboardParamsFalls back to defaults (day, full ticker list)

Define one DataError type with code (NOT_FOUND, UPSTREAM, RATE_LIMIT, NETWORK, INVALID) shared by the proxy and the client. Every error state in the UI maps from that code, so wording stays consistent and testable.

Success looks like:

  • lint, typecheck, tests and build all exit 0 with no warnings introduced;
  • the page shows 5 quote cards, a comparison chart that updates when the tabs change, and a ranking table;
  • stopping the proxy produces an error panel with Retry, not a blank page;

12. Supporting GitHub-driven feature evolution

The point of the architecture is that a GitHub issue or PR request can be mapped to a small, predictable set of files. Both humans and Bob can then implement it safely.

Extension points designed in

Likely requestWhere it landsExisting code touched
Add or swap a competitorconfig/companies.tsNone
New time window (e.g. 1 year)domain/windows.ts plus a tabNone beyond the config and WindowTabs
New chart or metricnew component in components/charts, pure function in domain/metrics.tsPage composition only
Different data providerNew MarketDataService implementation or yahooClient replacementNone in UI
User-selected company graph (the Part 2 example)New SymbolSearch control, reuse useSeries and PriceChart, new SelectedCompanyPanel, add an s URL param, relax the server allow-list to a validated patternPage gains one panel. Existing dashboards unchanged.

For the example feature, the acceptance criteria in docs/pr-feature-request-example.md map directly onto existing pieces: loading and error states come from ChartCard and DataError, “existing dashboards remain visible” is covered by the integration test, and symbol validation reuses the proxy's zod schema.

Repository conventions to add

  • Issue templates (.github/ISSUE_TEMPLATE/feature.yml, bug.yml): require “expected behavior” and “acceptance criteria” fields, which is what Bob needs to plan from.
  • Branch naming (already supported by CI triggers): feature/<slug>, fix/<slug>, bob/<slug> for AI-assisted branches.
  • PR template: keep it, and add a “Closes #<issue>” line so issue and PR stay linked. Update its validation block to the real commands from section 11.
  • CODEOWNERS and branch protection on main: require the CI job and one human approval. This keeps merging a human decision, in line with the README's note that Bob prepares and pushes branches but does not merge.
  • CONTRIBUTING.md or finance-app/README.md architecture section: layer rules, “where do I put X” table above, and validation commands. This is the context Bob reads first on every request.
  • Small, typed, tested seams: every feature PR should add or update tests in the same layer it changes. CI enforces it.

Issue to merge flow

#StepActor
1Issue opened from the feature template, with acceptance criteriaProduct owner
2Fetch the issue, map it to extension points (table above), propose a planBob
3Create bob/<slug> branch, implement with tests in the matching layersBob
